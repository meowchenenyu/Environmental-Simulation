記錄已在專案中實作或驗證的做法，供後續階段規劃時參考。未經實作驗證的建議應標示為假設，不與經驗混寫。

## 2026-11-20：以 SVG 地圖疊加網格完成階段 1 編輯器

### 情境與結果

既有首頁已經有以 SVG 繪製的島嶼插畫。本次在不更換既有地圖、不加入建置工具的前提下，加上可編輯地形的互動原型：使用者可選擇森林、草原、濕地或沙灘筆刷，在島上選取地塊並拖曳繪製；可放大縮小、復原與重做，並將地形修改保存在瀏覽器本機。海洋仍由島嶼外的底圖表示。

### 實作經驗

- **延用既有 SVG 畫布，疊上格子而非重畫地圖**：保留插畫和標示，格子以 SVG `clipPath` 限制在島嶼輪廓內。這讓地形工具快速成形，也避免地塊跑到海面上。
- **使用 SVG viewBox 網格作為編輯座標**：目前畫布為 `720 × 390`，切成 `18 × 10` 格，每格 `40 × 39`。檢視或點選位置時沿用 SVG 座標系，縮放時格子和插畫保持對齊。
- **筆刷改動採可逆紀錄**：每次格子修改保存前值與新值，復原與重做即可共用同一筆紀錄；鍵盤支援 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 和 `Ctrl/Cmd+Y`。
- **將可編輯資料與插畫分開**：使用透明色彩覆蓋層表示使用者修改，原始插畫仍是範例島底圖。沒有修改過的地塊保留原本畫面，不必先建立完整地圖資料集。
- **以版本化 key 保存在 localStorage**：目前 key 為 `archipelago-observatory:tidal-between:terrain:v1`。此方式適合單裝置原型，不會自動跨瀏覽器或跨裝置同步。
- **互動命中層需考慮插畫前景物件**：地圖上的生物圖示位於地形格上方；若前景 SVG 群組攔截 pointer event，就無法在圖示位置繪製。裝飾層應設定 `pointer-events: none`，讓事件抵達可編輯格子。
- **工具列需同時反映操作狀態**：進入／退出編輯模式時同步更新按鈕名稱、aria-pressed、筆刷工具、復原按鈕可用狀態與操作提示，減少使用者誤以為模擬正在改變地形。

### 未來可套用範圍

- 小型固定格網的 2D 地圖、關卡或場景編輯器，且已有 SVG 或向量插畫可作底圖。
- 使用有限種類筆刷的地圖標記、棲地分區、風險區域或熱度格覆蓋層。
- 原型階段需要快速加入選取、拖曳繪製、縮放和復原／重做的靜態網站。
- 單人、單瀏覽器的暫存設定或草稿；不可直接把 localStorage 當作帳號資料庫、可靠備份或多人同步方案。

### 已知限制與後續提醒

- 網格尺寸、格寬高和島嶼 clip path 目前都與 SVG 插畫耦合；若調整 viewBox 或輪廓，必須一起更新網格尺寸和遮罩。
- localStorage 只適用於目前網站來源及瀏覽器設定檔。進入階段 4 前，需設計穩定的島嶼 schema、匯入匯出與雲端版本策略。
- 目前只是地形外觀覆蓋，尚未影響物種棲地、族群或模擬規則。階段 2 應把地形格轉成模擬可以讀取的資料，並確保視覺顏色由同一份資料渲染。
- 目前格網固定為矩形，沒有可編輯海洋格；若產品需要改變島形或海岸線，需另行設計地圖生成與地形拓樸模型。

## 2026-11-20：建立資料驅動的確定性生態模擬

### 情境與結果

把原先只會改變日數的播放控制，接成每日模擬。新增 8 種生產者與消費者資料、季節和氣候狀態、植被資源、族群變化、簡化食物鏈和依棲地比例調整的遷移。日誌、物種卡、穩定度、環境指標與三種趨勢檢視都讀取模擬狀態。最近 30 個模擬步驟保存在本機，支援退回與重播。

### 實作經驗

- **讓模擬步進保持確定性**：`stepSimulation(previous, terrainEdits)` 只根據輸入狀態回傳下一狀態，不直接改寫舊狀態，也不使用隨機數。這讓播放、單步、回退、除錯與長期運算檢查能重現相同結果。
- **把物種參數集中管理**：棲地、食物、溫濕度範圍、繁殖方式、移動能力、成長率和死亡率集中在 `simulation.js` 的物種資料中。UI 卡片、食物關係、族群上限和圖表引用相同識別碼，減少多份數字逐漸不一致。
- **用本機格子變更推導棲地比例**：原型只儲存使用者改過的格子；模擬依格子推導森林、草原、濕地、沙灘比例，再影響食物回補、棲地適宜度和族群分布。這能讓地圖編輯與模擬互相影響，同時不必先建置完整 GIS 系統。
- **先用抽象的棲地分布表示遷移**：各動物族群保留在不同棲地間的比例，逐步向較適合的地形比例調整。這適合目前儀表板尺度，但並不代表個體有實際座標或路徑。
- **資源回補率需要多日觀察**：第一輪參數讓花蜜資源快速耗盡，90 日後樹蛙族群消失。調高植物回補、按降雨和棲地比例調節消耗後，再跑 90 日時基準地圖的物種與資源維持穩定。這只是可玩性參數校準，不是生態模型的科學驗證。
- **趨勢只能顯示真實已記錄的模擬日**：初始資料只有第 24 天一個點，不應補造第 18 至 23 天的平線。現在依實際序列產生圖表，歷史不足時重複顯示目前日期標籤，不宣稱存在未模擬的資料。
- **持久化結構需要版本化**：地形和模擬分別放在獨立 localStorage key（`...:terrain:v1`、`...:simulation:v1`）。新增資料欄位或更換模擬規則時，應考慮增加 schema 版本與載入時遷移，避免舊存檔在新版本無法讀取。

### 未來可套用範圍

- 前端單人沙盒、教學模擬與需要可重播狀態的遊戲原型。
- 想先驗證資源消耗、族群回饋與儀表板互動，再決定是否升級服務端模擬的專案。
- 小型網格地圖中，以區域比例代替個體路徑的早期模型。
- 可重現的回歸檢查：固定輸入狀態，多次步進後比較族群、資源與事件輸出。

### 已知限制與後續提醒

- 模擬採確定性、全島彙總和簡化成長公式；遷移表示棲地分布比例，不模擬個體座標、路徑或真實食物網參數。不可用作科學預測或教育評量標準。
- `metricsFor` 的穩定度是遊戲回饋指標，不是生態學量表；後續應在 UI 中保留「遊戲指標」定位。
- localStorage 僅支援目前瀏覽器來源與設定檔。跨裝置、分享、版本分支和可靠備份需等階段 4 的雲端資料設計。
- 物種圖卡目前全部列出，但進階圖鑑、逐格族群密度和更完整棲地因果關係仍可在之後擴充。

### 驗證紀錄

- JavaScript 語法檢查通過；固定狀態的多日模擬可重現，90 日運算中資源保持在 0–100、族群保持非負整數。
- 瀏覽器檢查確認地形編輯、保存後重載、復原／重做、單步推進、回退、播放／暫停和圖表切換能更新介面；瀏覽器 console 無 error。

## 2026-11-27：加入可重看的首次造訪教學

### 情境與結果

階段 3 需要讓新玩家快速掌握地圖、時間控制和生態趨勢。本次新增四步原生 HTML 對話框教學：首次載入時顯示，玩家可完成、略過或按 Escape 關閉；頂部「操作教學」按鈕可隨時從頭重看。完成狀態使用獨立的版本化 localStorage key 保存，不改動地形或模擬存檔。

### 實作經驗

- **以原生 `<dialog>` 承載非阻塞式導覽流程**：`showModal()` 提供模態焦點和 Escape 關閉行為，無需另加對話框套件。教學步驟由一組標題與文字資料渲染，前進按鈕在最後一步轉為開始探索。
- **略過和完成共用完成狀態**：略過、Escape 和走完最後一步都寫入同一個完成標記，避免下次造訪反覆彈出；重看入口不會清除這個狀態，也不會重設任何遊戲資料。
- **教學要對應實際介面和能力**：步驟說明範例島、地形筆刷、播放／單步／回退、事件日誌、趨勢切換和物種卡，避免承諾尚未存在的任務或存檔管理功能。
- **本機儲存讀寫失敗時仍保留當次可用性**：若 localStorage 不可用，對話框仍可開啟和關閉；只是無法記住已完成狀態，下次載入可能再次顯示。

### 未來可套用範圍

- 純 HTML／JavaScript 的單頁工具，需要可略過且可重看的首次使用導覽。
- 遊戲或模擬器已存在明確介面入口、但新玩家需要先掌握數個操作的情境。
- 單裝置偏好或導覽完成標記；不適用於跨裝置帳號進度、可靠備份或多人同步。

### 已知限制與驗證紀錄

- 目前是分步文字說明，沒有逐步高亮實際按鈕、限制玩家操作或自動執行任務；未來若要互動式教學，應另外設計對應的焦點管理和復原流程。
- `node --check app.js`、`node --check simulation.js` 和 `git diff --check` 通過。此環境的瀏覽器安全政策拒絕開啟 `file:` 本機預覽，因此尚未完成真實瀏覽器的首次彈出、Escape、略過與重看操作檢查。

## 2026-11-27：加入可重玩的 7 日生態挑戰

### 情境與結果

在自由探索之外加入一個可選的初階任務。玩家接受後，系統記錄開始時的模擬日；推進 7 天後，以模擬目前仍存活的物種數判定是否達到至少 6 種。任務進度另存於版本化 localStorage key，重載後可接續；玩家中途可以返回自由探索，模擬本身不會因此重設。

### 實作經驗

- **讓任務目標直接使用既有模擬指標**：完成條件沿用 `metricsFor(state).richness`，避免另造一套物種存活判定，並讓任務描述與總覽數字一致。
- **以開始日推導進度，而非重複存計數器**：挑戰只需保存開始日；已觀察天數、剩餘時間和進度列都由目前模擬日推導。回退模擬時任務也跟著目前時間重算，避免計數器與模擬歷史不同步。
- **可選任務不改變自由探索流程**：挑戰由明確入口開啟，預設仍是自由探索；中途退出只清除挑戰標記並保留島嶼和模擬存檔。
- **限制目標範圍讓首次任務容易理解**：以一週觀察和終點物種數做單一條件，避免同時引入資源門檻、連續天數或隱藏計分規則。

### 未來可套用範圍

- 以日數或回合數推進的瀏覽器遊戲與模擬器，可將任務存為起始回合並從目前狀態推導進度。
- 已有可靠指標（例如族群數、資源量或穩定度）的單人挑戰，能重用模型結果而非再做平行計分。
- 可中途退出且不破壞沙盒資料的可選目標；若任務需要跨分支、多人競賽或嚴格防作弊，需改由版本化存檔或服務端驗證。

### 已知限制與驗證紀錄

- 任務只檢查第 7 天的物種數，不保證這 7 天內族群一直穩定；玩家回退模擬時結果會按目前日數和狀態重算。
- `node --check app.js`、`node --check simulation.js` 和 `git diff --check` 通過。瀏覽器預覽仍受本機 `file:` URL 安全政策限制，尚未完成實際點擊和重載操作檢查。

## 2026-11-27：提供本機存檔管理與安全重設入口

### 情境與結果

地形與模擬已自動保存，但玩家缺少檢視進度、手動保存和清楚重設的入口。本次新增存檔管理對話框，顯示模擬日數與自訂地形格數，並提供立即保存、重新開始模擬及還原範例地形。兩種重設都先說明影響並要求確認：重新開始會保留自訂地形；還原地形會保留模擬進度，並重新計算棲地。

### 實作經驗

- **明確說明各類資料的重設範圍**：將模擬與地形分成兩個獨立操作，避免「重設」含義不明；每個確認訊息列出保留與清除的內容。
- **重新開始時清空依賴舊模擬日數的狀態**：模擬回到初始狀態時，同步清除 30 步回退歷史與以起始日計算的挑戰，並停止播放計時器。
- **還原地形需同步更新畫面與模擬**：清除 localStorage 地形、畫布覆蓋層、復原／重做堆疊和選取框，並重新計算棲地，避免畫面殘留已刪除格子。
- **保存動作應回報真實結果**：保存函式回傳成功與否，管理對話框只有在地形和模擬都寫入成功時才顯示成功訊息；儲存空間不足時提供錯誤提示。

### 未來可套用範圍

- 以 localStorage 保存多份互相獨立資料的單人 Web 原型，需要提供手動保存與清楚重設動作。
- 有些資料需要保留、另一些資料需要重置的編輯器或模擬工具；可用分項動作和確認文字降低誤刪。
- 不適用於需要可靠備份、跨裝置恢復、多存檔槽或帳號同步；這些需求仍需匯出格式或服務端存檔方案。

### 已知限制與驗證紀錄

- 目前只有目前瀏覽器的一份自動存檔，沒有命名存檔槽、下載備份或跨裝置恢復。
- `node --check app.js`、`node --check simulation.js` 和 `git diff --check` 通過。瀏覽器預覽仍受本機 `file:` URL 安全政策限制，尚未完成實際操作驗證。

## 2026-11-27：支援模擬日復原、重做與地形快照

### 情境與結果

原本只能回退模擬日，無法重做；重要時間點也沒有書籤。本次增加模擬日重做（與既有地形筆刷復原／重做分開），並可建立、載入和刪除快照。快照同時保存完整模擬狀態與地形，最多保留 10 份；舊版只含 `state` 和 `history` 的存檔仍可載入，缺少的新欄位會使用空陣列。

### 實作經驗

- **將時間線的未來狀態放入獨立重做堆疊**：復原時把目前狀態推入重做堆疊；重做時再推回復原歷史。推進新的一天或修改地形會清除重做分支，避免在不同模擬條件下重播舊未來。
- **重做分支和最近 30 日歷史一起保存**：重新載入仍可重做已回退的日期；若是建立新分支，必須同時更新 localStorage，否則舊的重做狀態會在重新載入後復活。
- **手動快照包含模型狀態及其輸入地形**：只保存族群與環境而不保存地形，恢復時結果會和保存時間點不一致。快照載入後清空目前時間線和地形筆刷歷史，再套用快照地形並同步棲地。
- **為快照數量設上限並拒絕靜默覆蓋**：最多 10 份，超過時要求先刪除一份，避免自動淘汰重要時間點；載入或刪除前先確認會覆蓋或移除的資料。

### 未來可套用範圍

- 確定性單人模擬、回合制工具與地圖編輯器，需要在可保存的狀態間回退／重做。
- 需要回到重要檢查點的個人沙盒；若狀態較大或需長期保存，應採增量快照、匯出備份或服務端版本管理。
- 編輯內容會影響運算結果時，快照需同時記錄狀態與其輸入資料（例如地形或規則版本）。

### 已知限制與驗證紀錄

- 快照保存完整狀態並以 localStorage 為基礎，最多 10 份；目前沒有自訂名稱、匯出或跨裝置同步。模擬重做堆疊和一般回退歷史各自最多 30 步。
- `node --check app.js`、`node --check simulation.js` 和 `git diff --check` 通過。瀏覽器預覽仍受本機 `file:` URL 安全政策限制，尚未完成實際回退、重做及快照還原驗證。

- **將環境收支寫成可單獨測試的純函式**：水量計算明確接收降雨、溫度、前日水量和棲地比例，回傳滲透、逕流、蒸散、淨變化及受上下限約束的存量，方便調整規則和驗證方向性。
- **讓地形改變影響環境機制**：濕地提高降雨滲透並降低逕流，森林降低蒸散；測試應檢查相對方向（濕地更多時保水較多、溫度更高時蒸散較強），避免只鎖定某一個數值。
- **把模型診斷存進狀態並延續到存檔驗證**：歷史／快照可以保留當時水循環收支；格式驗證接受舊存檔中沒有診斷欄位，但新欄位存在時檢查合理範圍。
- **用跨越門檻的事件說明變化**：只在水量跨入警戒或恢復區間時新增事件，避免每日重複警告；事件附上當日收支及可調整的棲地線索。
- **讓環境警戒連到實際生態效果**：以淡水可用率調整生產者生長，讓低水量可逐步壓低草叢與海草，而不是只新增一則警告；用相同天氣和地形比較高／低水量的植被變化。
- **讓危害條件可重現且設冷卻期**：野火只在水量低、溫度高且有足夠草本燃料時觸發，燒減草叢和花蜜，並記錄上次火災日以限制 60 天內重複發生；用明確設定模擬日與水量測試火災和冷卻邏輯。

### 未來可套用範圍

- 小型環境模擬或策略遊戲中，將降雨輸入、地表逕流、棲地滲透和蒸散分開表示，再把同一份收支用於視覺化和事件說明。
- 舊版存檔逐步加入新模擬診斷時，可採選填欄位相容策略：舊檔可讀，新存檔再嚴格驗證新欄位。
- 有警戒狀態的系統（缺水、資源短缺、溫度壓力），以門檻跨越事件取代每個週期重複提醒。

### 已知限制與驗證紀錄

- 這是為可解釋互動設計的簡化指標，沒有土壤深度、地形坡度、地下水、日照和實測天氣資料；不代表真實生態或水文預測。森林／濕地係數是遊戲平衡起點。範例島連續模擬 480 天水量介於 63.4–71.8；把地形改為低保水沙地後，同一期間最低降至 45.8，並觸發乾旱警戒與兩次間隔至少 60 天的野火。乾旱警戒目前設定在存量跨低於 50%，恢復則需回到 60%，以留出回復區間避免提示在門檻附近反覆閃動。
